4. NOTE: removed knight and queen lattice type to simply honeycomb implementation.

5. Implementation of a 'find right neighbour' function in order to select the right neighbour
    list depending on the site; this will be useful for the honeycomb lattice.
    Function name: get_neighbor_positions().

    Idea: since non-Bravais lattices have different nearest neighbour orientations
    the neighbour tuples are now made of 2 tuples, depending on the site 'parity' 
    (parity is computed as, given i and j as lattice site indeces, (i + j) % 2).
    For Bravais lattices (e.g., square) the tuple are identical.
    For non-Bravais lattices (e.g., hexagonal) the tuple differ.

    This is propagated to:
    - h_get_particle_energy(), d_get_particle_energy(): change the loop over 
        nearest neighbours;
    - run_cpu(), d_update(): compute dx, dy via get_neighbor_positions

    Introduced:
